# 方案三：可执行的只读项目 Agent

本阶段把“规划辅助”接成真正的后端工具循环。桌面聊天、DevOps、工作区任务中心共用持久化任务；模型提出结构化工具调用，后端校验并执行，再把带调用 ID 的结果回传模型。

## 使用

1. 打开 `release/Noosphere.exe` 或桌面 `Noosphere` 快捷方式。
2. 在顶部“工作区与任务”选择工作区，设置项目目录和默认模型。Gateway 中现有模型配置继续使用；Agent 当前支持 DeepSeek、OpenAI、OpenAI 兼容协议和配置为 OpenAI 兼容端点的 Ollama，具体模型仍需支持 tools。
3. 在聊天输入栏开启“只读 Agent”，发送目标，例如“查找项目启动入口，读取相关文件，并用引用说明调用过程”。关闭该开关仍是普通对话。
4. 或在 DevOps 的“项目只读 Agent”输入目标，点击“执行只读任务”。这里使用工作区默认模型。
5. 展开“Agent 执行记录”查看步骤、成功/失败、耗时、证据、源码行号、读取时 SHA-256 和时间。模型结论与工具证据分开显示。

聊天提供即时停止按钮。DevOps 页面切换后任务继续运行；所有任务可在顶部“工作区与任务”查看和取消。重开聊天可从已保存的任务链接读取后台结果，不重新请求模型。退出桌面应用会停止它管理的后端；下次启动将未完成任务标为中断，绝不自动重放。重新生成是用户主动发起的新任务，保留原来的 Agent 模式。

## 第一阶段的能力与限制

| 工具 | 内容 |
|---|---|
| project_list_files | 列出当前项目符合条件的源码/文本路径 |
| project_search | 不区分大小写的字面搜索，返回当前源码证据 |
| project_read_file | 项目相对路径读取，单次最多 200 行、单文件最多 1 MiB |
| project_context | 检索有效代码与已确认长期记忆，复核项目归属和来源版本 |
| system_processes / system_connections / system_services | 有界的 Windows 进程、连接、服务状态快照 |
| service_status | 查询指定服务状态；服务名经校验 |

系统工具随 DevOps 模块启用。搜索、读取不要求先建立索引；`project_context` 的代码检索使用方案二的索引与记忆机制，索引完成后更有效。

每个任务最多 6 次模型请求、12 次工具调用，执行阶段总时限 120 秒、每个工具 15 秒，每次模型输出最多 2,048 token。完全相同的工具及参数重复两次就停止，模型请求不隐式重试。上下文、扫描量和工具输出均有上限，大项目搜索可能只是部分结果。队列等待时间不包含在后端执行时限中；聊天还有独立等待超时。

项目根目录和项目 ID 在提交时固定，模型配置在实际开始执行时固定。项目绑定变更会在下一次模型/工具边界停止任务。读取使用根目录约束，排除符号链接、隐藏目录、依赖/构建目录、已知凭据文件，并遮盖常见凭据格式；这不是对任意文本中所有秘密的识别保证。

只读模式不开放改文件、任意命令、运行测试、启动/停止服务或自动回滚。第二阶段通过单独的“操作提案”模式开放需要逐项确认的文件修改、固定测试和服务启停，见 [操作审批与恢复](agent-reviewed-actions.md)。模型提出的操作建议不代表执行成功，只有工具记录可以证明本次做过的检查。操作审批与只读调用的记录分开保存。

## 协议与成本

DeepSeek 使用标准非思考模式 tool calls：保留 assistant.tool_calls，再回传 role=tool 和一致的 tool_call_id，不从自然语言中解析命令，不使用 beta strict 模式。参考 [DeepSeek 官方工具调用文档](https://api-docs.deepseek.com/guides/tool_calls/)。

工具结果发送到所选模型提供方参与后续推理。Gateway 记录每轮模型使用量与耗时；任务结果记录模型 ID、调用次数、输入/输出 token 和停止原因。重开记录不调用模型，主动重新执行会产生新的模型请求。

开发验证使用本地模拟模型、临时项目和独立数据目录；未调用用户的真实 DeepSeek 账户。具体测试和发布产物见 `EXECUTABLE_AGENT_VERIFICATION.md`。
