# 方案二：代码理解与长期记忆

## 使用方式

1. 在工作区选择项目目录，然后在 CodeLens 重新索引。旧的固定行数索引没有源码版本，不会作为可信来源注入新回答。
2. 在 Nebula 的“项目长期记忆”整理项目约定、设计决策、稳定偏好和已验证方案。默认保存为待确认，手动确认后参与检索。
3. AI 回答底部可以“整理为待确认记忆”。这会保存回答内容及原会话/消息标识；模型回答需要人工核实，不会自动升级为事实。
4. 内容修改后重新确认；“用新记录替代”会在一次原子提交中确认新记录并停用旧记录。旧记录保留，带有后继记录 ID。
5. 回答底部展开“本次提供给模型的依据”，查看代码文件、符号、行号、源码哈希或记忆版本、具体片段。编号是提供给模型的参考资料，不能保证模型的每一句话都受引用支持。

## 代码索引

- 普通函数、类、接口、枚举保持完整；较大类按成员切分，模块空隙保留。超过 12,000 字符的单元显式分段，超长行不丢弃。
- 片段 ID 来自文件、符号、类型与分段编号。前面插入注释不会使未变函数的向量失效；行号和整文件源码哈希仍更新。
- 保存 SHA-256 文件版本、片段内容版本、符号和保守的调用关系。调用关系仅做可确定的本文件解析；动态调用、跨文件导入等保留为 unresolved，不声称完整语义分析。
- 未变文件复用进程内 AST 缓存。重启后重新解析，但落盘内容与向量仍可复用。
- 完全未变记录跳过 LSM 写入、分词更新、嵌入和图重建。仅来源元数据变化时跳过嵌入和图重建。
- 向量内容变化时仍重建全图，但在读锁外构建，完成后一次切换；取消或嵌入失败保留上一份索引。此版本不是完全增量 HNSW 边维护。

## 记忆与引用约束

- 新数据存储在 `knowledge-<workspace ID>:` 命名空间。旧 Nebula 会话与聊天历史保留，不自动转为整理记忆。
- 支持 proposed / confirmed / rejected / superseded，revision 乐观锁冲突返回 409；替代操作还必须提供目标的 `supersedes_revision`。最多 500 条整理记忆/工作区，单条正文最多 16,000 字节。
- 来源为人工笔记、聊天快照或项目文件。文件来源仅接受项目内相对路径，解析符号链接后核对目录边界，文件上限 1 MiB。
- 所有记忆记录创建时的项目根目录，换根后原项目记忆停止参与上下文。文件来源另在创建和检索时校验版本；文件被修改或删除、记忆过期或被替代后不会参与上下文。失效记录仍可拒绝或停用，保留原始来源快照。
- 每次上下文最多 8 条，最多 16,000 个 Unicode 字符正文预算，单条最多约 4,000 字符。最多预检每个命名空间 60 个检索候选，长期记忆预留最多 3 条。
- 不监听文件变化，也不自动调用付费服务重新索引。新文件需要手动重新索引；失效提示只针对本次检索到的候选。
- 未配置真实 embedding 时显示“关键词与哈希向量检索”。DeepSeek 等聊天配置不等于已接入语义 embedding。已配置的 embedding 服务失败时，本次上下文检索明确显示失败，不静默称其成功。
- 会话保留回答时的引用快照；重新打开会话不会重新检索或重新计费。历史引用不代表当前文件仍相同。
- 检索失败或超时仍允许普通聊天，但明确显示本次回答未使用项目依据。

## 桌面接口

Tauri 命令：`list_knowledge`、`save_knowledge`、`prepare_context`，经现有本地鉴权转发。

- `GET /api/workspaces/{id}/knowledge`
- `POST /api/workspaces/{id}/knowledge`（完整记录；新记录省略 id，修改需要当前 revision）
- `POST /api/workspaces/{id}/context`（query、top_k）

上下文的项目绑定由后端读取；前端再次核对工作区与项目 ID。工作区切换会重置记忆编辑器，进行中的聊天结果只写回其源会话。

## 基准

Windows / Ryzen 5 5600、Go benchmark、128 维本地哈希向量，`-benchtime=3x`，2026-10-09 实测。仅测索引发布，不含 Python 解析、磁盘遍历或远程 embedding。样本小，有调度噪声，不能换算为整机加速比例。

| 片段数 | 完全未修改 | 修改一个片段 |
|---|---:|---:|
| 100 | 3.94 ms | 10.24 ms |
| 1,000 | 7.40 ms | 67.57 ms |

运行：`go test ./internal/nebula/engine -run '^$' -bench BenchmarkProjectIncremental -benchtime=3x -count=1`。

符号切分采用排序与区间查找，消除逐实体全表扫描；另有不依赖机器速度的实体访问次数回归测试。2026-10-10 内存夹具重复 5 次的中位数：1,000 函数 8.56 ms，2,000 函数 17.16 ms，4,000 函数 38.11 ms。该测试只测切分，不含 AST 解析。
