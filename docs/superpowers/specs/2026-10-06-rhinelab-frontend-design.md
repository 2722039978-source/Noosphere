# Noosphere 前端 RhineLabUI 完整替换方案

日期：2026-10-06

状态：用户已确认三维档案作为默认入口，保留 Noosphere 特性；实现与桌面验证见 ../plans/2026-10-06-rhinelab-frontend.md。

## 目标与范围

用户要求参照本地 RhineLabUI 的结构与文件内容，完整优化和替换项目前端。实施目标为 `new/frontend`；参考源为 `new/RhineLabUI/RhineLabUI`。保留 Noosphere 的名称、真实业务功能、已有会话和设置兼容性。

覆盖工作台、AI 对话、CodeLens、Nebula、DevOps、Gateway、设置，以及导航、按钮、表单、弹窗、搜索、加载、错误、空状态、主题和响应式布局。

## 当前实现与差距

- 技术栈已经是 React、TypeScript、Vite、Three.js、Radix、Tailwind，具备 MiSans 字体和 archive-cassette 模型。
- `app/routes.tsx` 默认打开 AI 对话，工作台位于 `/home`。
- `features/home/ArchiveCanvas.tsx` 当前只创建一列六份模型，通过线性插值抬升；没有参考工程的循环阵列、相机过渡、波浪传播和完整抽取归位状态。
- `app/layout.tsx` 与 `app/sidebar.tsx` 使用固定顶部栏和左侧模块目录，首页另有介绍文案、档案预览、模块目录及指标区域。
- 参考工程以原生 DOM 管理全屏舞台，场景依赖固定档案数据；不能将 `main.ts` 原样放入 React。
- 聊天已有独立流式运行时与 IndexedDB 存储，界面重构必须保留切页后继续生成、取消、会话检索定位及备份能力。

## 体验方案

### A. 全屏档案入口 + 统一业务工作区（推荐）

启动后进入 RhineLabUI 风格的全屏档案舞台。选择真实模块并访问后进入对应业务页面；业务工作区采用同一套字体、细线、编号、配色和导航语言，同时提供直接切换模块与返回档案入口的方式。

档案入口默认替代目前的介绍区、嵌入式预览与重复模块目录。启动动画可跳过，进入业务后不强制重播。设置提供启动页偏好，使频繁使用者可以直接进入 AI 对话。

优点：最接近参考工程的完整体验；业务操作保留直接入口。代价：需要调整启动路由、模块链接和相关回归用例。

### B. AI 对话默认入口 + 全面统一界面

默认仍打开 AI 对话，工作台升级为完整档案舞台，其余页面进行同等程度的组件与版式替换。

优点：保留现有启动习惯与路由语义。代价：默认打开时不会看到参考工程最具辨识度的三维档案体验。

### C. 将业务全部嵌入三维档案详情

每项功能都使用参考项目的左右详情构图。

不推荐：聊天、日志、代码片段和模型配置需要充足横向空间，持续保留大面积三维模型会压缩主要工作内容并增加渲染成本。

## 推荐视觉设计

- 以参考 `style.css`、`DESIGN.md` 和实际运行画面提取颜色、排版、细线及间距；沿用暖灰白底、黑色主文本、暖杏金选中状态和 MiSans。
- 保留 Noosphere 品牌。模型标签与舞台文案使用真实模块名称及编号，不引入参考项目的虚构身份、授权状态或研究档案。
- 全屏入口突出三维档案阵列、选中条目与访问动作。业务页面采用阅读和操作优先的档案式排版。
- 对话页面统一会话目录、消息阅读区、代码块、上下文选择、模型选择和输入区。数据页面统一标题、工具栏、筛选、列表、表格、详情与反馈。
- 浅色贴近参考；深色使用相同层级和状态语义。窄屏改用可操作的二维模块索引及抽屉导航，不将 1920×1080 舞台整体缩小。

## 代码组织与迁移边界

建议形成以下职责划分，并保留已有业务模块目录：

```text
src/
  app/                 路由、业务工作区外壳、导航
  components/ui/       统一按钮、输入、弹窗、列表与反馈组件
  features/home/       档案入口与 React 场景容器
    scene/             场景、材质、光照、运动、循环导航适配
  features/chat/       既有聊天功能与新界面
  features/{其他模块}/ 各模块业务与新界面
  styles/              主题变量、基础样式、外壳及场景样式
  stores/              既有状态及界面偏好
```

迁移对应关系：

| 参考文件 | Noosphere 中的用途 |
| --- | --- |
| `style.css` | 提取视觉系统与档案舞台布局，转换为可复用组件样式 |
| `scene.ts` | 接入 React 容器的实时三维场景 |
| `motion.ts`、`archive-loop.ts` | 抽取、归位、循环切换与波浪运动 |
| `appearance.ts`、`archive-lighting.ts` | 统一材质与光照 |
| `boot.ts`、`boot-motion.ts` | 可跳过、可关闭的 Noosphere 启动过渡 |
| `scrub-title.ts` | 快速切换标题的过渡行为 |
| `data.ts` | 仅参考接口组织，改用 Noosphere 模块注册数据 |
| `public/assets`、`public/fonts` | 按需复用资源并保留附带许可与来源说明 |

模块数量按真实能力确定，不为匹配参考的五列四十档案编造业务内容。模块注册表统一提供编号、名称、描述、路由与状态，避免首页和侧栏重复维护。

独立模型拆解查看器不列为业务必需功能；场景中的选中、抽取和返回动效列为迁移范围。是否另行提供模型查看器不影响业务界面替换。

## 运行与兼容要求

- 三维模块按需加载；业务页面不持续渲染首页场景。
- React 卸载、窗口隐藏、WebGL 失败与减少动态效果分别处理，释放 RAF、监听器、几何、材质、纹理、后处理和渲染器资源。
- 场景失败时仍能通过二维索引进入所有业务页面。
- 键盘导航仅在档案舞台获得操作焦点时生效，避免干扰搜索框、聊天输入、弹窗及输入法。
- 沿用 API、Tauri IPC、流式运行时、存储格式和后端凭证流程；仅在接入新界面必要时调整调用位置。
- 不复制参考项目的演示数据、不迁移其全局 DOM 入口、不依赖其目录才能运行构建后的前端。

## 验证与交付

1. 在独立浏览器存储下核对参考舞台与 Noosphere 界面，检查构图、字体、颜色、间距、场景材质和运动。
2. 构建检查 TypeScript 和 Vite，运行现有逻辑测试。
3. 回归七个页面以及主题、导航、弹窗、窄屏、键盘焦点和减少动态效果。
4. 回归聊天发送与停止、流式期间切页、历史检索定位、上下文、存储和备份，测试使用合成数据与模拟 IPC。
5. 覆盖 1920×1080、1440×960、900×600 和 390×844；核对场景失败时的降级操作。
6. 检查生产资源路径及桌面 CSP，确认模型与字体能够从构建产物加载。
7. 交付变更说明、验证结果及实际截图；前端构建完成不等同于已更新 `release/Noosphere.exe`，桌面打包状态单独记录。
