# 方案三第二阶段：操作预览、确认执行与恢复

第二阶段在只读 Agent 上增加了三类可审核操作。模型只能提出操作，不能批准自己的操作。每一项都保存在本机操作日志中，由桌面界面的明确点击触发执行。

## 使用入口

聊天输入栏先开启“只读 Agent”，再开启“操作提案”；模式标签会变为“Agent · 审批”。例如：

> 读取 main.go，把唯一的启动说明注释改得清晰一些，提出修改预览，并提出一次 Go 测试。

或者在 DevOps 勾选“允许操作提案（执行前确认）”，输入目标后点击“生成操作提案”。

回复下展开“Agent 执行记录”，再展开“操作预览与执行”中的具体操作。任务中心也提供同一套入口。核对修改前/修改后、项目目录或命令后，点击“确认执行此操作”；不需要的提案可拒绝。模型任务完成只表示本轮分析/提案结束，具体操作的状态以审批记录为准。

## 支持的操作

| 类型 | 预览和执行 | 恢复方式 |
|---|---|---|
| 文件修改 | 对已有文件进行一次唯一匹配的文本替换，或在已有目录下创建文件。完整展示修改前后。 | 按已保存原文恢复；新建文件则恢复为不存在。当前内容必须仍匹配本次写入版本。 |
| 项目测试 | 固定的 `go test -timeout 60s ./...`、`python -m unittest discover -v`、`node --test`，可指定项目内测试目录。 | 可停止测试进程及其子进程；测试代码产生的文件、网络等副作用不能自动回滚。 |
| Windows 服务 | 单个服务启动或停止，预览服务名、命令、原状态和目标状态。 | 当前状态符合预期时，可恢复到原来的运行/停止状态。权限不足会失败，不自动提权。 |

服务操作随 DevOps 模块开启。测试运行环境必须已安装；Go/Python 会在 PATH 及应用所在项目的本地运行环境中查找，Python 的绝对配置路径优先。固定命令不代表测试代码被沙箱隔离，仅应批准可信项目的测试。

## 执行边界

- 每个模型任务最多保存 3 个操作提案，原来的模型/工具调用预算继续有效。
- 文件限项目内 UTF-8 普通文本，最多 64 KiB；父目录必须存在。排除链接、隐藏/依赖/构建路径及已知凭据文件。检测到常见凭据格式的文件拒绝通过 Agent 修改。
- 不开放删除任意文件、任意 shell 命令、安装依赖、服务配置修改或自动提权。
- 执行文件操作前检查保存的原文哈希；恢复时检查修改后的哈希。外部改动会产生冲突，不覆盖后来的内容。操作中与外部程序同时写入不属于事务性文件锁保证，建议避免同时编辑同一文件。
- 提案固定工作区根目录与项目 ID。项目绑定变更后，旧提案拒绝执行或恢复，需回到对应项目核查。
- 测试/服务操作一次只运行一个，单次最长 90 秒，工具原始输出读取上限 32 KiB。Windows 子进程在运行前纳入 Job 管理，取消和后端退出时清理其派生进程；不弹出命令行窗口。
- 不向测试进程传递 Noosphere 本地 API token，以及名称包含 TOKEN/API_KEY/PASSWORD/SECRET 的环境变量。因此依赖这些环境变量的测试可能需要改为独立运行。
- 确认与恢复均针对后台保存的不可变操作 ID；重复确认被拒绝。网络报错后界面重新读取后台状态，避免凭旧状态重复操作。

## 重启和失败

提案及原文保存在应用数据目录下的 `agent-actions`。待确认提案在重启后保留。执行前先记录进行中状态，执行后再记录结果；意外退出时未完成的动作标为“执行中断，需核查”，不自动重放。

中断的文件操作可以尝试“恢复原文件”：若文件已是原文，直接记录已恢复；若等于本次写入版本，则恢复原文；若既不是原文也不是本次版本，则拒绝覆盖。服务动作也要先核对实际状态。每个文件单独确认和恢复，不承诺多文件修改的一次性原子回滚。

执行结果出现在原操作记录中，不自动再调用模型。可以核对结果后继续发起下一轮分析。测试失败保留日志，服务失败保留错误；都不会伪装成已完成。

本阶段保留现有 RhineLabUI 视觉、普通聊天和只读模式。验证过程完全不使用 Computer Use，使用命令行、自动化测试和无头浏览器；实际发布验证仅操作隔离临时项目，不修改用户项目或真实 Windows 服务。
